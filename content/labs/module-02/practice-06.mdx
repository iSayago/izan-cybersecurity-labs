## Objetivo

Utilizar Wireshark para reconocer indicadores de compromiso en capturas de red y explicar qué preguntas responde cada filtro antes de formular una conclusión.

## Contexto y entorno del laboratorio

La práctica se realiza en la máquina Windows Server del laboratorio, con Wireshark 4.4.0 instalado. Las capturas analizadas son **PCAP de ejemplo proporcionados por el curso**, no tráfico generado por una víctima real. La evidencia demuestra el método de análisis, no una intrusión ocurrida en producción.

Los archivos utilizados incluyen `Ioc_TCPHalfScanAttempt`, `Ioc_TCPNullScanAttempt`, `Ioc_OSFingerprintingAttempt`, `Ioc_BruteForceAttempt` y `Ioc_PonyMalware`.

## Procedimiento realizado

1. Se abre Wireshark y se cargan las capturas desde la carpeta de sample PCAP del módulo.
2. Para el intento de TCP Half Scan se aplican filtros de SYN y SYN+ACK:

```text
tcp.flags.syn==1
tcp.flags.syn==1 and tcp.flags.ack==1
```

3. Para el intento de TCP Null Scan se revisan las respuestas RST/ACK desde el objetivo:

```text
ip.src==10.10.10.12 and tcp.flags==0x014
```

4. Para OS fingerprinting se buscan SYN con ventanas pequeñas:

```text
(tcp.flags==0x02)&&(tcp.window_size < 1025)
```

5. Para la fuerza bruta FTP se filtran las respuestas del servidor:

```text
ftp.response.code==220
```

6. Para el PCAP de Pony Malware se filtran las peticiones POST y se revisan los dominios y rutas solicitadas:

```text
http.request.method=="POST"
```

## Análisis de resultados

**Observado:**

- En el PCAP de half scan aparecen numerosos SYN y respuestas SYN+ACK/RST compatibles con un barrido de puertos.
- El PCAP de null scan muestra respuestas RST/ACK desde el objetivo; el patrón debe interpretarse junto con los flags del intento.
- El filtro de OS fingerprinting devuelve SYN con `tcp.window_size` inferior a 1025.
- El PCAP de FTP contiene respuestas del servicio y un volumen de intentos compatible con fuerza bruta.
- El PCAP de Pony contiene consultas DNS y peticiones HTTP POST hacia un servidor remoto, incluyendo rutas y nombres de archivo usados por malware.

**Interpretación:** Wireshark permite pasar de "hay mucho tráfico" a una hipótesis concreta: tipo de actividad, origen, destino, protocolo y secuencia. Ningún filtro aislado demuestra compromiso; la conclusión depende de la combinación de flags, puertos, repetición y contexto.

También es importante distinguir el análisis de un PCAP de ejemplo de la captura de una máquina comprometida. En este caso, el valor está en el método: seleccionar una pregunta, aplicar un filtro, leer la secuencia y documentar el límite de la conclusión.

## Conclusiones

El análisis de red es una actividad de preguntas y verificación. Los filtros son herramientas para reducir el ruido, no para sustituir el razonamiento. La práctica refuerza la necesidad de conservar capturas, registrar los filtros aplicados y explicar qué se ha observado frente a lo que se interpreta.

## Aprendizajes

- Un filtro de Wireshark reduce el ruido, pero la conclusión depende del contexto y de varios paquetes.
- Los PCAP de ejemplo permiten practicar el método sin confundirlos con evidencia de una víctima real.
