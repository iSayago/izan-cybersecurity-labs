## Objetivo

Identificar los servicios accesibles en la máquina objetivo `10.10.10.12` y comparar el resultado de un escaneo SYN con el de una conexión TCP completa. El reconocimiento permite construir el mapa de superficie de ataque que se utiliza en los ejercicios posteriores.

## Contexto y entorno del laboratorio

La máquina atacante es una VM Ubuntu con Nmap 7.92. El objetivo es el servidor de laboratorio `10.10.10.12`, que aloja LuxuryTreats y otros servicios. La red es un entorno aislado del curso; las direcciones no pertenecen a sistemas de producción.

## Procedimiento realizado

1. Se abre una terminal en la máquina atacante y se accede como root.
2. Se ejecuta un SYN scan sobre el objetivo:

```bash
nmap -sS 10.10.10.12
```

3. Se ejecuta un TCP connect scan con temporización agresiva:

```bash
nmap -sT -T4 10.10.10.12
```

4. Se comparan los puertos y servicios devueltos por ambas variantes.

El flag `-sS` realiza un escaneo SYN sin completar el three-way handshake; `-sT` completa la conexión TCP; `-T4` aumenta la agresividad y reduce el tiempo del escaneo.

## Análisis de resultados

**Observado:** ambos escaneos identifican la misma superficie principal: FTP, HTTP, RPC/SMB, MSMQ, RDP y WinRM. La salida muestra `Host is up` y el tiempo total del escaneo. El MAC aparece como `02:15:5D:37:2C:C0`.

**Interpretación:** la máquina expone más servicios de los necesarios para una aplicación web. FTP y HTTP explican los vectores usados en los ejercicios siguientes: el FTP será objetivo de fuerza bruta y el sitio web de las inyecciones. RDP y WinRM amplían la superficie de administración y deben justificarse y segmentarse.

El patrón de muchos SYN y respuestas RST/SYN-ACK es un IoC de reconocimiento. En el SOC debe correlacionarse con la IP de origen, la frecuencia y los puertos consultados; un escaneo puntual no es suficiente para concluir una intrusión.

## Conclusiones

El reconocimiento convierte una dirección IP en un mapa de servicios. La comparación entre SYN y connect scan ayuda a entender qué deja cada técnica en la red y por qué la telemetría de firewall/IDS es relevante. La lección práctica es reducir la exposición y monitorizar patrones de sondeo, no solo alertas de exploit.

## Aprendizajes

- El reconocimiento convierte una IP en un mapa de servicios y superficies de ataque.
- SYN y TCP connect dejan patrones distintos; el análisis debe incluir la telemetría de red, no solo el resultado de Nmap.
